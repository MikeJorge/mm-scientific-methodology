Learning & application · 2 of 3

One need, two specifications, two decisions

A correct total can conceal a deficit in a particular period.

Synthetic teaching example. The arithmetic below illustrates requirements conformity and adequacy to a hypothetical use. Its acceptance is limited to the declared didactic ConOps and fixtures. It is not validation of an agronomic model or an assessment performed with external developers.

The need and intended use

A hypothetical analyst needs to identify every deficit period in a twelve-period horizon, so those periods can be investigated. Demand and supply use the same illustrative unit. There is no storage, carryover or compensation between periods. This last condition is a stipulation of the exercise; applying it to a real system would require domain justification.

The code can implement this stipulated rule. It cannot decide whether a real system has carryover, whether the observations are representative, or whether a proposed intervention is scientifically justified.

The input contract

C-INPUT-1 requires exactly twelve ordered periods, P01–P12; supply and demand arrays of twelve integers in the range 0–10000; and the unit demo_units_per_period. All four fields are required. Extra fields, invalid types, duplicate/reordered periods and missing observations are rejected. A recorded zero is valid; a missing value is not silently converted to zero.

The fixture is declared before execution.

Two identified specifications

SRS-AGGREGATE v1

Validate the input, calculate total supply and total demand, and report their difference. This specification does not promise a list of deficit periods.

SRS-PERIOD v1

Validate the input and report every period in which demand exceeds supply, with its deficit. Preserve period identity and order. Equality is not a deficit.

The first specification is deliberately insufficient for the stated per-period need. An aggregate routine may pass verification against SRS-AGGREGATE, but it fails verification against SRS-PERIOD and is rejected for this ConOps. It has not passed the same requirement that it violates.

A small implementation

The downloadable Python module validates the shared contract before either function. The essential computations are shown below; the kit contains the complete validation code, fixtures, tests and runner.

# After C-INPUT-1 has been checked:
balance = sum(supply) - sum(demand)

deficits = [
    {"period": p, "deficit": d - s}
    for p, s, d in zip(periods, supply, demand)

Inspect or run the example

Download the learning and fresh-reader kit

Extract the ZIP, read README.md, then run python run_demo.py with Python 3.10 or newer. On Windows, py -3 run_demo.py is also suitable. Only the standard library is used. The command writes a new receipt and preserves the preparation evidence.

Kit contents include the complete example, both specifications, predeclared fixtures and results, the conceptual diagram source, the transfer task, assessor guide, blank observation template and checksums.
